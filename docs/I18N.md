# Internationalisation (en / hi / mr)

The staff-facing app supports English (`en`, default), Hindi (`hi`) and Marathi (`mr`).
The active language is stored in the `ms_locale` cookie (set by the language switcher) and
read by the root layout, which sets `<html lang>` and provides only that locale's messages.

## Layout

```
lib/i18n/
  config.ts          Locale, LOCALES, DEFAULT_LOCALE, LOCALE_COOKIE (plain module, safe everywhere)
  core.ts            translateWith(): interpolation + plurals + fallback (no catalogue)
  translate.ts       translate(locale, key, params) over the FULL catalogue (server/tests)
  translate-client.ts  Translator type + dict-bound translator (bundle-safe)
  server.ts          getT(), getLocale()           (server components / actions)
  provider.tsx       I18nProvider, useT(), useLocale()   ("use client")
  actions.ts         setLocale(locale) server action
  intl.ts            intlLocale(locale) -> 'hi-IN-u-nu-latn' (Latin digits)
  messages/<area>.ts one catalogue file per area, merged in messages/index.ts
  GLOSSARY.md        approved Hindi/Marathi terminology and style guide
```

## Adding strings (area files)

Edit ONLY your own area file in `lib/i18n/messages/` (`common`, `shell`, `auth`, `landing`,
`today`, `patients`, `patient-detail`, `visits`, `reports`, `calls`, `documents`, `opd`,
`settings`, `clinical`). Never edit another area's file; if you need a generic word, use or
(rarely) append to `common`.

```ts
export const calls = defineArea({
  en: { "calls.filter.overdue": "Overdue", "calls.summary": "{name} was called {count} times" },
  hi: { "calls.filter.overdue": "विलंबित",  "calls.summary": "{name} को {count} बार कॉल किया गया" },
  mr: { "calls.filter.overdue": "उशीर झालेले", "calls.summary": "{name} ला {count} वेळा कॉल केला" },
});
```

- Keys are flat and dotted, prefixed by the area: `calls.filter.overdue`. The area agent for
  `patient-detail` uses the prefix `patientDetail.`. Pattern: `area.screen.element` (camelCase segments).
- `en` defines the key set. `hi` and `mr` must have exactly the same keys: a missing or extra
  key is a TypeScript error (`defineArea`), and `lib/i18n/parity.test.ts` also checks it.
- Every `{param}` in `en` must appear in `hi` and `mr`; the parity test fails if a translation drops one.
- Use the wording in `GLOSSARY.md`. Add new recurring terms there.
- If hi/mr text is legitimately identical to English (brand, unit), list the key in your file:
  `export const untranslated: string[] = ["calls.unit.bpm"];`. Entries must be real keys of that file.
- Key names must be unique across all areas (tested).

## No hardcoded user-facing strings

Everything a user can read or hear goes through `t()`: visible text, `aria-label`, `title`,
`placeholder`, `alt`, toasts, confirm dialogs, validation messages, `document.title`/metadata,
and **error/success messages returned by server actions** (call `getT()` inside the action).
Do not translate: brand names (MatruSetu, WhatsApp), user/patient data, ids, units.

## Server vs client components (identical syntax)

```tsx
// Server component / server action
import { getT } from "@/lib/i18n/server";
const { t, locale } = await getT();
t("calls.filter.overdue");
t("calls.summary", { name, count: 3 });

// Client component
"use client";
import { useT, useLocale } from "@/lib/i18n/provider";
const t = useT();
t("calls.filter.overdue");
```

Client files must not import `@/lib/i18n` (index), `translate.ts` or `messages` (these pull in every
locale). Import constants from `@/lib/i18n/config` and hooks from `@/lib/i18n/provider`. A server
component gets constants from `config.ts` (a plain module), never from a `"use client"` file.
Pass the `locale` (not a function) to client components if they need to format dates.

`t` is typed: `t("typo")` is a compile error (`MessageKey`).

## Plurals and parameters

Plural messages use suffixes on one base key and a numeric `count` param:

```ts
"calls.attempts_one": "{count} attempt",
"calls.attempts_other": "{count} attempts",
// optional: "calls.attempts_zero": "No attempts yet",   (used only when count === 0)
//           "_two", "_few", "_many" for languages that need them
t("calls.attempts", { count: n });   // note: base key, no suffix
```

Lookup: `_zero` (count 0 only) -> `_<Intl.PluralRules category>` -> `_other` -> bare key. Provide at
least `_one` and `_other` in every locale (Hindi treats 0 as "one"). Plain `{name}` interpolation:
`t("key", { name })`. Unknown placeholders are left as-is; missing keys render the key
(English fallback applies on the server; hi/mr completeness is enforced by types and tests).

## Dates, numbers, relative time

Use `lib/format.ts` with the locale: `formatDate(iso, locale)`, `formatShortDate`, `relativeDays(iso, today, locale)`,
`formatNumber`, `formatDateWith(iso, options, locale)`. All use Latin digits (`-u-nu-latn`) for
clinical readability. For ad-hoc Intl use `intlLocale(locale)` from `@/lib/i18n/intl`. Replace any
direct `'en-IN'` with it. (date-fns ships a `hi` locale but no `mr`; prefer Intl.)

## Fonts and layout

Devanagari falls back to Noto Sans Devanagari (`--font-devanagari`). `:lang(hi)`/`:lang(mr)`
rules in `app/globals.css` raise line-height and remove negative tracking. Hindi/Marathi text
is usually 10-30% longer: avoid fixed widths and `truncate` on buttons; check at 375px.

## Verification

1. `npm run lint && npm run typecheck && npm test`. The parity tests fail on key mismatches, dropped
   placeholders, untranslated (identical-to-English) values and duplicate keys across areas.
2. Switch language with the switcher and click through your screens in hi and mr: no clipped
   matras, no overflow, no English left (including tooltips, aria-labels, toasts).
3. Translations are drafts until the Clinical Lead has reviewed the hi/mr clinical wording.
